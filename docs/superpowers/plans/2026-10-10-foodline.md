# FoodLine DC Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A working local web app — simulated SMS food finder + live demand map for DC Wards 7 & 8 — that runs with one command and survives a live virtual demo.

**Architecture:** Next.js app in `web/`. A pure, tested engine in `web/lib/engine/` (location resolution, hours, lookup, replies, gap scoring) is called by route handlers. Requests are appended to an NDJSON log and broadcast over an in-process event bus to SSE clients. The map is MapLibre with local GeoJSON layers only (offline-safe).

**Tech Stack:** Next 16.4.0, React 19.3, TypeScript 5.9, Tailwind 4.3, motion 14, maplibre-gl, vitest, @anthropic-ai/sdk (optional), qrcode.

**Spec:** `docs/superpowers/specs/2026-10-10-foodline-design.md`

## Global Constraints
- Never invent resources, hours or statistics; every on-screen number shows its source.
- Works with no network and no API key (templates; local map layers; self-hosted fonts via `geist` package / next/font/local).
- Log only `{ts, zip, lat, lng (3 dp), need, lang, source}`.
- Sample data always labelled "Sample".
- Demo runs on `next build && next start -H 0.0.0.0 -p 3000`; one root command `npm run demo`.

## Review Focus
1. Lower-case/abbreviated cross streets ("minnesota ave & benning rd") → must resolve to the intersection; test in Task 2.
2. Spanish message with no location ("necesito comida") → Spanish prompt for a location; test in Task 4.
3. "more" with no prior search → helpful prompt, not a crash; test in Task 4.
4. Seasonal/monthly resources at "open now" → excluded with no false "open"; test in Task 3.
5. SSE blocked (tunnel) → map still updates via polling within ~1 s; verified in Task 7 manually.
